@topic w4-eda :: Exploratory Data Analysis :: Cara "melihat data dengan disiplin" sebelum percaya pada pola apa pun.
@intro
- EDA = disciplined first look: tujuannya memahami structure, variation, relationships, dan analytical risk — bukan membuktikan strategi.
- Siklus EDA 4 langkah: Summarise → Visualise → Question → Validate. EDA itu "percakapan dengan data" sebelum modeling formal.
- Workflow 5 stage: Profile → Univariate view → Bivariate view → Text view → Sentiment view.
- Sebelum bikin chart, cek dataset readiness: raw fields preserved, clean fields, derived fields documented, flags, data dictionary, log reconciled.
- Cleaning nanya "bisa gak variabel ini dipercaya?"; Exploration nanya "variabel ini nunjukin apa — dan apa yang GAK bisa dibuktikan?"
- Prinsip inti: chart dan sentiment summary BUKAN kesimpulan. Mereka bukti diagnostik yang harus dicek dulu sebelum jadi rekomendasi brand.
- Mantra Week 4: Explore first. Interpret cautiously. Validate before strategy.
@concept w4-eda-loop :: Siklus EDA 4 Langkah :: Kerangka eksplorasi dari slide: data diringkas, divisualisasikan, dipertanyakan, lalu divalidasi sebelum polanya dianggap kuat.
@vars
Summarise :: hitung jumlah record, kategori, missingness, dan metrik deskriptif dasar. KENAPA: angka dulu, feeling belakangan.
Visualise :: pakai chart untuk mengekspos pola frekuensi, distribusi, waktu, dan relasi. KENAPA: mata menangkap pola dan anomali lebih cepat daripada tabel mentah.
Question :: identifikasi pola yang mengejutkan, anomali, dan tempat yang masih rawan data quality. KENAPA: pola aneh itu pertanyaan, bukan jawaban.
Validate :: cek apakah polanya bertahan setelah filtering, cleaning rules, dan tampilan alternatif. KENAPA: pola yang gugur satu kali filter bukan temuan.
@concept w4-eda-readiness :: Dataset Readiness :: Syarat sebelum eksplorasi: dataset bersih masih menjaga bukti mentah, audit fields, dan variabel analisis kunci.
@vars
Raw fields preserved :: review_text_raw, date_raw, channel_raw tetap disimpan. Fungsi: bisa audit dan recovery kalau cleaning salah.
Clean fields created :: review_text_clean, date_clean, channel_clean siap jadi input chart yang konsisten.
Derived fields documented :: days_since_review, sentiment_label, issue_topic harus ada rumusnya — biar reproducible.
Flags available :: missing_date_flag, duplicate_flag, language_flag — untuk filtering yang transparan.
Data dictionary updated :: tipe field, source field, allowed values, cleaning rule — mencegah salah tafsir.
Log reconciled :: jumlah baris sebelum vs sesudah filtering bisa dijelaskan — membangun kepercayaan pada temuan.
@table Why Exploration Matters
| Exploratory finding | Brand analytics risk | Managerial implication |
| Negative reviews spike after a campaign | Campaign may have raised expectations or exposed service gaps | Investigate timing before blaming creative strategy |
| One channel dominates complaint volume | The issue may be channel-specific, not brand-wide | Prioritise service recovery by channel |
| Frequent words are generic | Word frequency may reflect noise, not brand associations | Remove stopwords and validate themes |
| Sentiment score conflicts with star rating | Model or language context may be unreliable | Use manual checks before making claims |
| High average rating hides bimodal reviews | Mean is insufficient when customer experiences are polarized | Segment or inspect distribution |
@table Exploratory Workflow 5 Stage
| Stage | Analyst action | Output |
| 1. Profile | Count rows, fields, blanks, valid ranges | Dataset snapshot |
| 2. Univariate view | Summarise one variable at a time | Frequency table, histogram, boxplot |
| 3. Bivariate view | Compare two variables | Cross-tab, grouped bar, scatter plot |
| 4. Text view | Clean text, count terms, inspect examples | Word frequency, tags, sample quotes |
| 5. Sentiment view | Generate and manually validate labels | Sentiment distribution + validation note |
@table Dataset Readiness Before Exploration
| Readiness item | Minimum check | Why it matters |
| Raw fields preserved | review_text_raw, date_raw, channel_raw retained | Allows audit and recovery |
| Clean fields created | review_text_clean, date_clean, channel_clean | Creates consistent chart input |
| Derived fields documented | days_since_review, sentiment_label, issue_topic | Makes formulas reproducible |
| Flags available | missing_date_flag, duplicate_flag, language_flag | Supports transparent filtering |
| Data dictionary updated | Field type, source field, allowed values, cleaning rule | Prevents interpretation ambiguity |
| Log reconciled | Rows before and after filtering can be explained | Builds trust in findings |
@trap Chart = kesimpulan :: Slide menegaskan: charts dan sentiment summary bukan konklusi dengan sendirinya — mereka diagnostic evidence yang harus dicek dulu. Langsung lompat ke rekomendasi brand dari satu chart itu justru yang dicegah Week 4.
@trap Chart tanpa jejak field :: Aturan slide: "No chart should leave the analyst's desk" tanpa jawaban jelas untuk "cleaned field mana yang menghasilkan figure ini?" Kalau gak bisa dilacak ke field + filtering rule, chart itu gak boleh dipakai di report.

Brand kosmetik fiktif "GlowLab" baru jalanin kampanye #GlowUp. Dua minggu setelahnya, review negatif naik jelas. Manajemen langsung menyimpulkan: "kreatif kampanyenya gagal, ganti agency!"

@topic w4-metrics :: Descriptive Metrics (frekuensi, distribusi, cross-tab, tren) :: Metrik yang tepat untuk pertanyaan yang tepat — how often, how much, when, who, what themes, how confident.
@intro
- Pertanyaan menentukan metrik: How often → count/share; How much → mean/median/min/max; When → trend; Who/where → cross-tab; What themes → term frequency; How confident → sample size, missing %, validation rate.
- Frequency analysis: untuk data kategorikal (issue type, platform, channel). Count tinggi = "sering di dataset ini", BUKAN otomatis "paling penting di pasar".
- Distribution: satu angka rata-rata bisa nyembunyiin polarisasi, skew, outlier, subgrup — makanya distribusi sering lebih berguna daripada average.
- Cross-tab: bandingkan kategori lintas dimensi kategorikal lain (sentiment × platform). Kunci: pakai ROW percentage dengan denominator yang benar.
- Trend exploration: kapan sinyal berubah? Tapi attribution kampanye butuh bukti lebih kuat dari sekadar spike visual.
- Angka N (total) harus selalu dilaporkan bareng persentase — % tanpa N itu gak bisa dinilai.
@concept w4-metric-fit :: Selecting Descriptive Metrics :: Pasangan pertanyaan-metrik dari slide: tipe pertanyaan analitis menentukan metrik deskriptif dan visualisasinya.
@vars
How often? :: Count, percentage, share → bar chart / Pareto chart. Contoh: share of complaints by issue type.
How much? :: Mean, median, min, max → histogram / boxplot. Contoh: distribution of order value or rating.
When? :: Trend, period comparison → line chart / heatmap. Contoh: review volume by week after campaign.
Who/where? :: Group percentage, cross-tab → stacked bar / matrix. Contoh: sentiment by platform or store.
What themes? :: Term frequency, co-occurrence → word cloud / tag cloud. Contoh: most repeated service attributes.
How confident? :: Sample size, missing %, validation rate → checklist table. Contoh: manual sentiment validation agreement.
@concept w4-denominator :: Denominator Cross-Tab :: Dalam cross-tab, persentase dihitung PER BARIS (dibagi total channel itu sendiri), bukan terhadap seluruh data — salah denominator = salah baca.
@vars
Row % (benar) :: tiap baris channel dibagi total review channel tersebut; jumlah tiap baris = 100%. Ini yang dipakai slide W4 (sentiment by platform).
Salah denominator :: membandingkan count mentah antar channel yang jumlah reviewnya beda jauh — channel dengan review terbanyak otomatis kelihatan "paling banyak komplain".
Pooled % :: persentase gabungan semua channel — berguna untuk gambaran umum, tapi menyembunyikan channel ekstrem (mis. CS chat yang 45% negatif).

@trap Count tinggi = penting :: Slide: high count berarti "frequent in this dataset", bukan otomatis "most important for the whole market". Sampling bias WAJIB dinyatakan — dataset review bukan sensus seluruh pasar.

@example Hitung share tiap tema dari tabel frekuensi :: Slide W4 · Frequency Analysis
@soal
Tabel frekuensi slide W4: Delivery delay 42, Staff attitude 31, App problem 26, Price concern 19. Total coded mentions N = 140 (empat tema = 118 sisanya "other").
(a) Hitung share tiap tema terhadap N = 140.
(b) Berapa persen mention yang masuk kategori "other"?
(c) Slide versi improved figure menyebut "Delivery and staff issues account for 51% of coded mentions" — hitung ulang, setujukah kamu?
@step Tentukan denominator :: Semua share dihitung terhadap TOTAL coded mentions (N = 140), bukan terhadap 118. KENAPA: 30% di slide hanya mungkin kalau 42 dibagi 140 — cek: 42/140 = 0.3 pas.
| Tema | Count | Hitungan share | Share |
| Delivery delay | 42 | 42/140 | 30% |
| Staff attitude | 31 | 31/140 | 22% |
| App problem | 26 | 26/140 | 19% |
| Price concern | 19 | 19/140 | 14% |
@step Hitung other :: Mention lain = N dikurangi empat tema = 140 - 118 = 22. Share = 22/140 = 15.7% (dibulatkan ≈ 16%). Ini bagian yang sering kelewat — pie chart 4 slice aja gak mewakili 100% data.
@step Cek klaim "delivery + staff = 51%" :: (42 + 31)/140 = 73/140 = 52.1%. Slide menulis 51% — itu pembulatan kasar dari 30% + 22% = 52%. Angka presisinya 52.1%. Flag halus: kesimpulannya tetap sah (dua tema terbesar), tapi angka yang benar 52.1%.
@answer (a) Delivery 30% (42/140), Staff 22% (31/140), App 19% (26/140), Price 14% (19/140). (b) Other = 22 mention = 15.7% (≈16%). (c) Hitungan ulang: 73/140 = 52.1%, bukan 51% seperti tertulis di slide improved figure — slide membulatkan; kesimpulan dua-tema-dominan tetap berdiri.
@uses w4-metric-fit, w4-denominator
@check 42/140*100 ~ 30.0
@check 31/140*100 ~ 22.1
@check 26/140*100 ~ 18.6
@check 19/140*100 ~ 13.6
@check (140-42-31-26-19)/140*100 ~ 15.7
@check (42+31)/140*100 ~ 52.1
@end

@example Mean 3.9 vs median 4.0 — rata-rata yang menutupi polarisasi :: Slide W4 · Distribution Analysis
@soal
Rating Kopi Senja (rekonstruksi 50 review yang cocok persis dengan angka slide): 2 bintang = 9 review, 3 bintang = 10 review, 4 bintang = 8 review, 5 bintang = 23 review. Slide melaporkan: mean 3.9, median 4.0, low-star 18%, high-star 62%.
(a) Hitung mean, median, low-star share, high-star share dari data ini.
(b) Kenapa mean 3.9 itu menyesatkan kalau dibaca sendirian?
(c) Apa implikasi brand-nya?
@step Hitung mean :: Mean = total bintang dibagi jumlah review. Sum = 9×2 + 10×3 + 8×4 + 23×5 = 18 + 30 + 32 + 115 = 195. Mean = 195/50 = 3.9. KENAPA: tunjukkan dari mana 3.9 berasal — angka gak boleh muncul tiba-tiba.
@step Hitung median :: Urutkan: posisi 1–9 adalah 2★, posisi 10–19 adalah 3★, posisi 20–27 adalah 4★, posisi 28–50 adalah 5★. Median = rata-rata posisi ke-25 dan ke-26 = dua-duanya 4★ → median 4.0. Median lebih tinggi dari mean karena ekor kiri (rating rendah) menarik mean ke bawah.
@step Hitung low-star dan high-star share :: Low-star (1–2★) = 9/50 = 18%. High-star (4–5★) = 8 + 23 = 31 dari 50 = 62%. Distribusi inicondong positif tapi punya benjolan nyata di bawah — pengalaman pelanggan terpolarisasi.
@step Interpretasi :: Mean 3.9 "kelihatan sehat" tapi menyembunyikan 18% pelanggan yang kasih bintang rendah — persis interpretation risk di slide. Median 4.0 konsisten dengan mayoritas positif, tapi pain points 18% itu tetap harus didiagnosis. Ini bukan distribusi normal — dua kelompok (sangat puas vs kecewa) menumpuk di ujung.
@answer (a) Mean = 195/50 = 3.9; median = 4.0; low-star = 9/50 = 18%; high-star = 31/50 = 62% — semua cocok dengan slide. (b) Mean 3.9 menyatukan dua populasi berbeda: 62% yang puas dan 18% yang kecewa; angka tunggal itu menyembunyikan polarisasi (interpretation risk: "hides low-rating pain points"). (c) Implikasi: diagnosa kelompok low-star (siapa, channel mana, keluhan apa) sambil melindungi kekuatan 62% high-star — jangan puas dengan "rata-rata 3.9 aman".
@uses w4-metric-fit
@check 9+10+8+23 == 50
@check (9*2+10*3+8*4+23*5)/50 ~ 3.9
@check 9/50*100 ~ 18.0
@check (8+23)/50*100 ~ 62.0
@end

@example Cross-tab: denominator yang benar :: Slide W4 · Cross-Tabulation
@soal
Cross-tab sentiment × platform dari slide (row %): Google 54/21/25, Instagram 68/19/13, E-commerce 43/18/39, CS chat 31/24/45 (Pos/Neu/Neg). Jumlah review per platform: Google 120, Instagram 160, E-commerce 90, CS chat 40.
(a) Platform mana yang paling bermasalah, dan kenapa gak bisa dijawab pakai count mentah?
(b) Hitung persentase negatif gabungan (pooled) seluruh platform.
(c) Kenapa pooled % justru menyesembunyikan masalah CS chat?
@step Baca row % dengan denominator yang benar :: Angka 45% negatif di CS chat artinya 45% dari review CS chat — dibagi 40 (total CS chat), BUKAN dibagi total 410. Tiap baris jumlahnya 100%: cek CS chat 31 + 24 + 45 = 100.
@step Hitung count negatif per platform :: Count negatif = row % × N platform. Google: 25% × 120 = 30. Instagram: 13% × 160 = 20.8. E-commerce: 39% × 90 = 35.1. CS chat: 45% × 40 = 18. KENAPA: dengan count mentah, Google (30) kelihatan "terburuk" padahal persentase terburuk adalah CS chat — jumlah review beda jauh.
@step Hitung pooled negative :: Total negatif = 30 + 20.8 + 35.1 + 18 = 103.9 dari total 410 review → 25.3%. Angka tunggal ini kesannya "seperempat saja negatif" — moderat.
@step Bandingkan pooled vs per-channel :: Pooled 25.3% menyembunyikan rentang 13% (Instagram) sampai 45% (CS chat). Masalahnya channel-specific (problem-resolution context di CS chat), jadi rekomendasi yang benar: prioritise service recovery by channel — bukan program perbaikan brand-wide yang seragam.
@answer (a) CS chat paling bermasalah (45% negatif). Count mentah menyesatkan karena jumlah review tiap platform beda (40 vs 160) — makanya wajib row %. (b) Pooled negatif = 103.9/410 = 25.3%. (c) Pooled menyamarkan channel ekstrem: CS chat 45% dan E-commerce 39% "tenggelam" dalam rata-rata 25.3% — padahal keduanya butuh prioritas perbaikan yang berbeda dari Instagram.
@uses w4-denominator, w4-metric-fit
@check 31+24+45 == 100
@check 0.25*120+0.13*160+0.39*90+0.45*40 ~ 103.9
@check (0.25*120+0.13*160+0.39*90+0.45*40)/410*100 ~ 25.3
@check 120+160+90+40 == 410
@end

@topic w4-viz :: Visualisasi yang Jujur (chart choice, integrity, storytelling) :: Chart yang tepat untuk tugas analitisnya, integritas visual yang bisa diaudit, dan interpretasi yang mengalah ke pertanyaan brand.
@intro
- Visualisasi itu analytical communication: harus accurate, readable, honest, dan terikat ke satu pertanyaan keputusan brand — bukan dekorasi.
- Chart choice ditentukan oleh analytical task: compare categories, change over time, distribution, part-to-whole, relationship, text themes.
- Visual integrity checklist 6 item: question fit, field traceability, scale honesty, label clarity, sample disclosure, caution statement.
- Slide W4 menilai: "accuracy and defensibility matter more than decorative design" — chart cantik yang gak bisa dipertanggungjawabkan gagal.
- Decorative chart (pie banyak slice, tanpa N, tanpa implikasi aksi) harus di-upgrade jadi decision-ready figure.
- Visual storytelling = lead with the question: Question → Evidence → Interpretation → Caution → Next step.
@concept w4-chart-choice :: Choosing the Right Chart :: Tabel keputusan dari slide: task analitis → best chart → kapan harus dihindari.
@vars
Compare categories :: Bar chart, ranked bar, Pareto. Hindari: pie chart dengan banyak slice.
Show change over time :: Line chart, time-series bar. Hindari: kategori yang gak berurutan dipakai seolah time series.
Show distribution :: Histogram, boxplot, density view. Hindari: cuma nampilkan average.
Show part-to-whole :: Stacked bar, 100% stacked bar, donut untuk sedikit grup. Hindari: membandingkan banyak segmen kecil.
Show relationship :: Scatter plot, bubble plot. Hindari: menyimpulkan causality dari correlation.
Show text themes :: Word cloud, tag cloud, frequency bar. Hindari: menganggap ukuran kata sebagai insight final.
@concept w4-integrity :: Visual Integrity Checklist :: Enam pertanyaan yang harus lulus semua sebelum chart dipakai di report — dipakai juga sebagai rubric gallery critique.
@vars
Question fit :: Apakah chart ini menjawab pertanyaan brand yang dimaksud? Chart yang cantik tapi menjawab pertanyaan lain = gagal.
Field traceability :: Bisakah analyst menunjuk field persis dan filtering rule yang menghasilkan chart ini?
Scale honesty :: Apakah axes, baselines, dan ranges transparan (gak ada axis terpotong yang melebih-lebihkan perubahan)?
Label clarity :: Apakah units, categories, dan time periods terbaca tanpa perlu menebak?
Sample disclosure :: Apakah sample size dan sumber data kelihatan di chart-nya?
Caution statement :: Apakah interpretasinya menghindari klaim kausal yang gak didukung?
@concept w4-storytelling :: Visual Storytelling: Lead With the Question :: Chart W4 bukan gambar lepas — dia menghubungkan pertanyaan keputusan brand, bukti visual, dan interpretasi hati-hati dalam 5 komponen.
@vars
Question :: keputusan brand apa yang dibantu chart ini? Contoh: "Which issue deserves immediate recovery action?"
Evidence :: pola apa yang terlihat di data? Contoh: "Delivery delay appears in 30% of coded issue mentions."
Interpretation :: pola ini mengisyaratkan apa? Contoh: "Customers may be experiencing fulfilment friction."
Caution :: apa yang BELUM bisa diklaim? Contoh: "This does not prove delivery is the root cause without sample review."
Next step :: apa yang harus analyst lakukan sekarang? Contoh: "Inspect negative delivery reviews and compare by channel/date."
@table Choosing the Right Chart (Slide W4)
| Analytical task | Best chart choices | Avoid when |
| Compare categories | Bar chart, ranked bar, Pareto | Using pie charts with many slices |
| Show change over time | Line chart, time-series bar | Using unsorted categories as if they were time |
| Show distribution | Histogram, boxplot, density view | Only showing an average |

@topic w4-sentiment :: Preliminary Sentiment & Interpretation Ladder :: Sentiment untuk triage dengan validasi manual, dan tangga interpretasi description → association → causality.
@intro
- Sentiment pipeline 4 stage: Text preparation → Token/theme extraction → Sentiment labelling → Distribution view — tiap stage punya validation question sendiri.
- Sentiment bisa: triage teks prioritas, membandingkan tone antar platform/periode, menandai tema bermuatan negatif, mendukung hipotesis awal, dan membimbing sampling kualitatif.
- Sentiment TIDAK bisa sendirian: membaca emosi sejati tanpa konteks, menemukan root cause, membuktikan representativitas pasar, atau membuktikan kausalitas kampanye → sentimen.
- Phrasing aman: "preliminary sentiment suggests..." — bukan "customers feel..." — sampai output model divalidasi terhadap sample texts.
- Validasi 6 langkah: sample review (30–50 komentar), edge cases, rating cross-check, theme cross-check, source comparison, documentation.
- Kenapa butuh manusia: sarcasm, mixed tone, bahasa/slang lokal, kata berlawanan (expensive but worth it), dan teks tanpa isi (No comment).
- Integrasi sinyal: rating + issue topic + platform + date + sentiment dibaca BERSAMA, bukan sendiri-sendiri.
- Interpretation ladder: Description (apa yang terlihat) → Association (apa yang bervariasi bersama) → Causality (apa menyebabkan apa — butuh desain & bukti kuat). Output W4 harus berhenti di Description dan Association hati-hati.
@concept w4-sentiment-pipeline :: Preliminary Sentiment Pipeline :: Empat tahap pengolahan teks menjadi label sentiment, masing-masing dengan pertanyaan validasi yang harus dijawab.
@vars
Text preparation :: bersihkan casing, URLs, spasi berulang, noise. Pertanyaan validasi: did cleaning remove meaning?
Token/theme extraction :: hitung kata, frasa, atau topik terkode. Pertanyaan: are frequent words meaningful?
Sentiment labelling :: klasifikasi positive / neutral / negative. Pertanyaan: does the label match human reading?
Distribution view :: rangkum sentiment per platform / waktu / tema. Pertanyaan: does the pattern survive cross-checks?
@concept w4-sentiment-limits :: Sentiment: Can vs Cannot Prove :: Batas klaim sentiment awal — daftar yang bisa didukung vs yang gak bisa dibuktikan sendirian.
@vars
Can: triage :: memprioritaskan teks mana yang butuh dibaca manusia dulu.
Can: compare tone :: membandingkan tone antar platform atau periode (dengan catatan platform bias).
Can: flag themes :: menandai tema dengan tone negatif tinggi untuk investigasi.
Cannot: true emotion :: emosi pelanggan sejati tanpa konteks — label model bisa salah baca.
Cannot: root cause :: akar kekecewaan — sentiment nunjukin ADA keluhan, bukan KENAPA.
Cannot: representativeness :: apakah isu ini mewakili seluruh pasar — sampling bias wajib dinyatakan.
Cannot: causality :: kampanye menyebabkan pergeseran sentiment — butuh desain bukti lebih kuat.
@concept w4-validation-steps :: Validasi Sentiment 6 Langkah :: Prosedur dari slide agar label otomatis layak dipakai untuk keputusan brand.
@vars
Sample review :: baca 30–50 komentar terpilih acak. Kriteria: label harus cocok dengan interpretasi manusia.
Edge cases :: periksa sarcasm, mixed tone, slang, bahasa lokal. Kriteria: kasus ragu-ragu ditandai.
Rating cross-check :: bandingkan star rating dengan label sentiment. Kriteria: konflik harus dijelaskan.
Theme cross-check :: cek apakah sentiment negatif menggerombol per issue type. Kriteria: hindari klaim "negatif semua" yang generik.
Source comparison :: bandingkan sentiment antar platform. Kriteria: nyatakan platform bias dan konteksnya.
Documentation :: catat metode, sample size, error, aturan koreksi. Kriteria: hasil bisa diaudit ulang.
@concept w4-ladder :: Interpretation Ladder :: Tiga anak tangga klaim dari slide — description, association, causality — semakin naik, semakin banyak bukti yang dituntut.
@vars
1. Description :: what is visible? Contoh: "Delivery mentions are the most frequent issue category." Hanya melaporkan apa yang ada di data.
2. Association :: what varies together? Contoh: "Negative sentiment appears higher in e-commerce reviews than Instagram comments." Dua hal bergerak bersama — belum ada klaim sebab.
3. Causality :: what caused what? Contoh: "The campaign caused negative delivery sentiment." Menuntut stronger design and evidence (eksperimen, kontrol, timeline).
Aturan W4 :: output Week 4 harus mayoritas berhenti di Description dan Association hati-hati. Klaim kausal tanpa desain pendukung = pelanggaran.
