############################################################
@topic w3-clean :: Data Cleaning & Quality Dimensions :: Cleaning sebagai lapisan kontrol antara observasi mentah dan kesimpulan manajerial — bukan kosmetik.
@intro
- Data cleaning = proses sistematis mendeteksi, mengoreksi, menstandarkan, menandai (flag), atau mendokumentasikan masalah data supaya analisis mencerminkan unit, periode, dan konstruk yang dimaksud.
- Cleaning yang baik TIDAK menghapus record yang "mengganggu" — cleaning membedakan error, outlier valid, informasi hilang, dan keterbatasan data.
- 4 langkah inti (bukan linear sekali jalan, tapi siklus per masalah): Detect → Decide → Transform → Validate, lalu semuanya di-Document.
- Data-Cleaning Workflow lengkap versi kelas (6 langkah): Preserve raw file → Profile data → Define rules → Apply transformations → Validate output → Log decisions.
- Audit logic kunci: tiap transformasi harus bisa dilacak — source field → rule applied → new field/flag → validation result.
- Kesalahan data kecil bisa mengubah prioritas bisnis: review duplikat menggembungkan tingkat keparahan isu; error tanggal mendistorsi recency; noise kategori memecah tema brand jadi beberapa label palsu.
@concept w3-cleandef :: Data Cleaning :: Proses sistematis mendeteksi, mengoreksi, menstandarkan, menandai, atau mendokumentasikan masalah data supaya analisis tetap mencerminkan unit, periode, dan konstruk yang dimaksud — bukan menghapus record yang merepotkan.
@vars
Detect :: temukan masalah secara sistematis (profiling: hitung blank, duplikat, rentang nilai)
Decide :: pilih aturan penanganan BERDASARKAN TUJUAN analisis, bukan asal buang
Transform :: buat variabel yang konsisten (field cleaned/derived baru, raw tetap utuh)
Validate :: cek jumlah record dan logika sebelum & sesudah transformasi
Document :: catat aturan dan alasan supaya bisa diaudit ulang
@concept w3-qualitydim :: 7 Data Quality Dimensions :: Tujuh sudut pandang untuk menilai kualitas data brand sebelum dipercaya jadi dasar chart, segmen, atau rekomendasi.
@vars
Completeness :: apakah field wajib terisi? contoh cek: % missing review_date, rating, order_value
Uniqueness :: apakah satu observasi nyata dihitung satu kali? contoh cek: review_id atau kombinasi teks-tanggal-user yang duplikat
Validity :: apakah nilai mengikuti aturan yang diharapkan? contoh cek: rating antara 1-5, tanggal valid
Consistency :: apakah kategori dan format terstandardisasi? contoh cek: penamaan store/channel konsisten
Accuracy :: apakah nilai mencerminkan realita? contoh cek: tanggal mustahil atau order_value negatif ditandai
Timeliness :: apakah sesuai periode analisis? contoh cek: hanya record dalam jendela sampling
Relevance :: apakah field mendukung decision question? contoh cek: variabel terkait langsung ke isu brand

| Kategori | Contoh |

@trap Cleaning disamakan dengan "menghapus data aneh" :: Slide eksplisit: "Good cleaning does not erase inconvenient records." Outlier atau record yang terlihat janggal bisa jadi sinyal bisnis penting (pembeli besar, keluhan serius) — cleaning yang benar menandai (flag) dan menyelidiki dulu, bukan otomatis menghapus.
@trap Quality dinilai lepas dari tujuan analisis :: Slide menegaskan "Quality is judged against the analysis purpose, not in isolation." Field yang "kotor" untuk satu tujuan (mis. order_value untuk RFM) bisa jadi tidak relevan sama sekali untuk tujuan lain (mis. analisis sentiment teks) — jangan menilai satu standar kebersihan untuk semua dataset tanpa lihat tujuannya.

@topic w3-struct :: Struktur Data: Raw/Clean/Derived/Flag, Dictionary, DQ Log :: Definisikan unit of analysis per dataset, jenis field, dan dua dokumen wajib: data dictionary dan data-quality log.
@intro
- Sebelum cleaning, tentukan dulu apa yang direpresentasikan SATU BARIS untuk tiap jenis dataset — unit of analysis menentukan prioritas cleaning.
- 5 tipe dataset & unit-nya: Transaction (satu order), Interaction (satu touchpoint/event), Review (satu review publik), Social comment (satu komentar/reply/post), Survey (satu respons responden).
- 5 jenis field wajib dibedakan: Raw (bukti asli, JANGAN ditimpa), Cleaned (distandardisasi untuk analisis), Derived (sinyal analitis baru, mis. days_since_review), Flag (penanda isu/keputusan, mis. is_duplicate), Version (status dataset, mis. dataset_version = v1.1_cleaned).
- Data dictionary Week 3 punya 7 kolom wajib: field_name, field_type (raw/cleaned/derived/flag), data_type, allowed_values, source_field, cleaning_rule, missing_rule, notes.
- Data-quality log mencatat tiap keputusan cleaning penting dan dampaknya, dengan field minimum: Issue, Detection method, Rule applied, Rows affected, Verification (plus rationale, person/date pada versi lengkap).
- Prinsip audit: "The cleaned dataset should explain both the analysis result AND the cleaning process behind it" — dataset bersih tanpa log bukan evidence yang bisa diaudit.
@concept w3-fieldtype :: 5 Jenis Field (Raw/Cleaned/Derived/Flag/Version) :: Klasifikasi kolom dataset berdasarkan perannya dalam alur cleaning, supaya bukti asli tidak pernah hilang.
@vars
Raw field :: menyimpan bukti asli apa adanya. Contoh: review_text_raw = " Great!!! ". Jangan pernah ditimpa.
Cleaned field :: hasil standardisasi untuk analisis. Contoh: review_text_clean = "great". Aturan transformasinya harus transparan.
Derived field :: sinyal analitis baru yang dibuat dari field lain. Contoh: days_since_review, sentiment_label. Formula/model-nya harus didokumentasikan.
Flag field :: penanda isu atau keputusan cleaning. Contoh: is_duplicate, missing_rating_flag. Berguna untuk audit dan filtering.
Version field :: pelacak status dataset. Contoh: dataset_version = v1.1_cleaned. Mendukung reproducibility.
@concept w3-uoadataset :: Unit of Analysis per Jenis Dataset :: Definisi "satu baris" berbeda-beda per jenis dataset brand, dan menentukan prioritas cleaning-nya.
@vars
Transaction data :: satu baris = satu pembelian/order (customer_id, order_date, order_value). Prioritas cleaning: tanggal, ID, mata uang, duplikat.
Interaction data :: satu baris = satu touchpoint/event (customer_id, channel, event_time, event_type). Prioritas cleaning: taksonomi event, timestamp, aturan sesi.
Review data :: satu baris = satu review publik (review_id, rating, text, platform, date). Prioritas cleaning: teks, validitas rating, duplikat, bias sumber.
Social comment data :: satu baris = satu komentar/reply/post (post_id, comment_text, author_display, date). Prioritas cleaning: noise, bahasa, URL/emoji.
Survey data :: satu baris = satu respons responden (respondent_id, item skala, demografi). Prioritas cleaning: coding skala, missing, consent, outlier.
@table Data Dictionary Week 3: 7 Kolom Wajib
| Kolom | Definisi/penggunaan | Contoh isi |
| field_name | nama kolom persis di dataset | review_date_clean |
| field_type | raw / cleaned / derived / flag | cleaned |
| data_type | text / date / numeric / category | date |
| allowed_values | rentang atau daftar kategori valid | 2026-01-01 sampai 2026-08-20 |
| source_field | field asal yang dipakai | review_date_raw |
| cleaning_rule | transformasi/validasi yang diterapkan | DATEVALUE + format yyyy-mm-dd |
| missing_rule | cara menangani nilai kosong | flag, jangan diimputasi |
@table Data-Quality Log: Contoh 3 Entri (slide)
| Issue | Detection | Rule applied | Rows affected | Verification |
| Blank review_date | COUNTBLANK(review_date_raw) | Flag missing_date; exclude dari recency | 12 | baris excluded dihitung terpisah |
| Duplicate text-date-user | COUNTIFS user/date/text | Simpan import paling awal; flag duplikat | 8 | jumlah record direkonsiliasi |
| Channel spelling variation | Pivot unique values | Map IG/Instagram/instagram.com → Instagram | 35 | daftar kategori punya 4 nilai valid |
@trap Field cleaned menimpa field raw langsung :: Slide menegaskan raw field "Never overwrite it". Kalau review_text_raw langsung diubah jadi lowercase/trim di kolom yang SAMA, bukti asli hilang selamanya dan tidak bisa divalidasi ulang — WAJIB buat kolom baru (review_text_clean), raw tetap utuh di kolom aslinya.
@trap Data-quality log dianggap opsional kalau dataset "sudah kelihatan bersih" :: Prinsip audit slide: "A cleaned dataset without a log is not auditable evidence." Walau dataset akhirnya terlihat rapi, tanpa log analis lain tidak bisa tahu APA yang diubah dan KENAPA — log wajib ada bahkan untuk perubahan yang terasa kecil.

@topic w3-detect :: Deteksi Masalah Data (missing, duplikat, kategori, teks, tanggal, angka, outlier) :: Profiling untuk menemukan di mana dataset tidak lengkap, terduplikasi, tidak konsisten, tidak valid, atau berisiko analitis.
@intro
- Missing data punya 4 TIPE berbeda, bukan satu kotak "kosong" generik: Missing Completely at Random, Missing by Design, Missing due to Process Error, Meaningful Absence — tiap tipe beda tindakan yang tepat.
- Duplikat ada 2 level: Exact duplicate (ID/baris identik persis, biasanya dari import berulang) dan Near duplicate (user/tanggal/teks sama dengan variasi kecil, butuh aturan pencocokan eksplisit, bukan tebakan).
- Kategori tidak konsisten (mis. "IG", "instagram", "Instagram Ads", "instagram.com") diam-diam memecah satu grup analitis jadi banyak label — solusinya mapping table, bukan replace manual berulang tanpa dicatat.
- Masalah teks umum: spasi berlebih, huruf campur (mixed case), URL/mention, emoji, campur bahasa, spam/noise — tiap masalah punya pertimbangan cleaning sendiri (emoji/negasi JANGAN dihapus membabi buta karena bisa membawa makna).
- Masalah tanggal umum: format campur, tanggal relatif ("2 hari lalu" harus dijangkarkan ke tanggal koleksi), timezone, tanggal tidak valid (31/02, tanggal masa depan), jam hilang, window mismatch.
- Masalah angka umum: rating berupa teks/di luar rentang, order_value dengan simbol mata uang/pemisah ribuan/nilai negatif, quantity desimal/nol, discount tersimpan sebagai 20 vs 0.20, engagement dengan sufiks K/M.
- Outlier BUKAN otomatis error — bisa jadi sinyal bisnis (premium buyer, isu servis serius, lonjakan engagement dari campaign/krisis) — perlu investigasi/triangulasi sebelum diputuskan.
@concept w3-missing4 :: 4 Tipe Missing Data :: Klasifikasi kenapa sebuah nilai kosong, menentukan tindakan cleaning yang tepat.
@vars
Missing Completely at Random :: tidak ada hubungan jelas dengan record itu (mis. beberapa komentar blank tanpa pola). Aksi: flag, nilai proporsinya.
Missing by Design :: memang tidak dikumpulkan untuk sumber/unit itu (mis. tidak ada order_value di review publik). Aksi: dokumentasikan keterbatasan; pakai proxy hanya kalau dijustifikasi.
Missing due to Process Error :: kegagalan koleksi atau entry (mis. tanggal hilang setelah scraping/import). Aksi: cek sumber; perbaiki kalau bisa diaudit.
Meaningful Absence :: kosong itu sendiri MEMBAWA MAKNA (mis. tidak ada mention brand dalam pencarian topik umum). Aksi: kode sebagai "absent" kalau relevan secara analitis.
@concept w3-dupdetect :: Deteksi Duplikat: Exact vs Near :: Dua level duplikasi yang butuh cara deteksi berbeda.
@vars
Exact duplicate :: ID sama atau baris identik penuh, sering dari import berulang/copy-paste. Bisa dihapus setelah raw copy disimpan.
Near duplicate :: user/tanggal/teks sama dengan variasi kecil, umum di review/komentar/CRM export. Butuh aturan pencocokan yang didokumentasikan.
COUNTIF transaction duplicate :: =COUNTIF(order_id, order_id) > 1
COUNTIFS review duplicate :: =COUNTIFS(user, user, date, date, text_clean, text_clean) > 1
@table Missing Data: 4 Tipe × Contoh Brand × Aksi
| Tipe | Contoh brand | Aksi yang direkomendasikan |
| Missing Completely at Random | Beberapa komentar blank tanpa pola jelas | Flag; nilai proporsinya |
| Missing by Design | Tidak ada order_value di review publik | Dokumentasikan keterbatasan; proxy hanya jika dijustifikasi |
| Missing due to Process Error | Tanggal hilang setelah scraping/import | Cek sumber; perbaiki jika bisa diaudit |
| Meaningful Absence | Tidak ada mention brand pada pencarian topik generik | Kode sebagai absent jika relevan analitis |
@table Excel Quick Checks untuk Deteksi
| Masalah | Fungsi Excel |
| Cek blank | =COUNTBLANK(range), =COUNTIF(range,"") |
| Cek duplikat transaksi | =COUNTIF(order_id, order_id) > 1 |
| Cek duplikat review | =COUNTIFS(user,user,date,date,text_clean,text_clean) > 1 |
@trap Semua nilai kosong dianggap "data hilang" yang harus diisi :: Meaningful Absence adalah kosong yang MEMANG bermakna (mis. brand memang tidak disebut) — mengisi nilai itu (imputasi) justru merusak makna. Sebelum memutuskan tindakan, tentukan dulu tipe missing-nya (4 tipe), baru pilih aksi; jangan langsung imputasi semua blank.
@trap Near duplicate dianggap sama proses deteksinya dengan exact duplicate :: Exact duplicate cukup dicek ID/baris identik. Near duplicate (mis. review sama tapi salah satu ada typo/emoji tambahan) butuh ATURAN PENCOCOKAN eksplisit yang didokumentasikan (mis. kombinasi user+date+text_clean) — bukan sekadar "kelihatan mirip", karena itu tidak reproducible oleh analis lain.

@example Kopi Nusa: klasifikasikan 4 nilai kosong ke 4 tipe missing :: Kasus latihan
@soal
Dataset Kopi Nusa punya 4 kasus kosong: (1) rating kosong pada beberapa review Instagram (Instagram memang tidak punya fitur rating bintang), (2) 3 baris review_text kosong tanpa pola jelas dari platform manapun, (3) tanggal kosong pada 5 baris yang diimpor dari file Excel yang corrupt saat proses scraping, (4) dalam analisis pencarian mention kompetitor, Kopi Nusa TIDAK disebut sama sekali pada 40 dari 120 post yang membahas "kopi lokal Jakarta" secara umum.
(a) Klasifikasikan tiap kasus ke satu dari 4 tipe missing data.
(b) Tentukan aksi yang tepat untuk masing-masing.
@step Klasifikasikan kasus 1 :: Instagram memang tidak punya kolom rating sama sekali (bukan gagal terisi, memang tidak ada fiturnya) → Missing by Design.
@step Klasifikasikan kasus 2 dan 3 :: Kasus 2 (3 baris review_text kosong tanpa pola) → tidak ada penjelasan sistematis → Missing Completely at Random. Kasus 3 (tanggal kosong akibat file corrupt saat scraping) → kegagalan proses teknis yang jelas penyebabnya → Missing due to Process Error.
@step Klasifikasikan kasus 4 :: "Kopi Nusa tidak disebut" dalam 40 dari 120 post pencarian topik umum itu sendiri adalah TEMUAN (brand tidak top-of-mind di topik itu) — kosongnya bermakna analitis → Meaningful Absence.

@topic w3-transform :: Transformasi & Excel (mapping, tanggal, rule template, quality check) :: Ubah field raw jadi variabel siap analisis pakai mapping table, fungsi Excel standar, dan rule template R01-R05.
@intro
- Category mapping table = tabel transparan raw_value → standard_value → rule_note, diimplementasikan dengan XLOOKUP(raw, map_raw, map_standard, "CHECK") — nilai yang tidak ketemu di mapping otomatis kelihatan sebagai "CHECK" untuk diinvestigasi, bukan diam-diam salah map.
- Date preparation 5 langkah: Raw date → Parse date (DATEVALUE/aturan manual) → Validate (tanggal valid & dalam jendela sample) → Reference date (tanggal koleksi atau tanggal terbaru) → Derived variable (days_since_event).
- 9 fungsi Excel wajib dikenal: TRIM (spasi), CLEAN (karakter non-print), LOWER/PROPER (case), XLOOKUP (mapping kategori), IF+ISBLANK (flag missing), COUNTIFS (cari duplikat), NUMBERVALUE (teks ke angka), IFERROR (tangani error konversi), TEXT(...,"yyyy-mm") (grouping bulan untuk tren).
- Transformation Rule Template terdiri 5 kolom: Rule ID, Source field, Condition, Action, New field/flag — R01 sampai R05 adalah 5 rule contoh standar dari slide.
- Quality checks sebelum analisis mencakup 10 item checklist (preservasi raw, rekonsiliasi jumlah record, flag duplikat, validasi tanggal, inspeksi outlier, definisi row jelas, completeness check, standardisasi kategori, range check numerik, dokumentasi limitation).
- Reproducibility diuji dengan pertanyaan: kalau raw file + log diberikan ke mahasiswa lain, bisakah mereka hasilkan cleaned dataset yang SAMA PERSIS?
@formula w3-mapping :: XLOOKUP untuk Category Mapping :: \text{channel\_clean} = \text{XLOOKUP(raw\_channel, map\_raw, map\_standard, "CHECK")}
@vars
raw\_channel :: nilai kategori mentah dari sumber (mis. "IG", "GMaps", "Tokped")
map\_raw :: kolom daftar semua nilai mentah yang dikenal di mapping table
map\_standard :: kolom nilai standar yang sepadan di mapping table
"CHECK" :: nilai default kalau raw_channel TIDAK ditemukan di mapping table — sinyal untuk diinvestigasi, bukan dibiarkan salah diam-diam
@vars
Rule ID :: kode unik rule (R01, R02, ...) untuk dirujuk di log dan dictionary
Source field :: field asal yang diperiksa rule ini
Condition :: syarat yang memicu aksi (mis. "blank", "<1 or >5", "duplicate order_id")
Action :: tindakan yang diambil (leave blank+flag, set invalid flag, replace dengan standar, TRIM+LOWER, dst)
New field/flag :: nama field/flag baru yang dihasilkan
@table Transformation Rule Template R01-R05 (slide)
| Rule ID | Source field | Condition | Action | New field/flag |
| R01 | review_date_raw | blank | leave blank; missing_date_flag = 1 | review_date_clean; missing_date_flag |
| R02 | rating_raw | <1 atau >5 | set rating_valid_flag = 0; exclude dari rata-rata rating | rating_valid_flag |
| R03 | channel_raw | cocok mapping table | ganti dengan kategori standar | channel_clean |
| R04 | review_text_raw | spasi berlebih / case campur | TRIM dan LOWER; simpan raw tetap ada | review_text_clean |
| R05 | order_id | order_id duplikat | flag; simpan record lengkap pertama | duplicate_flag |
@table 9 Fungsi Excel Wajib × Kegunaan
| Fungsi | Masalah yang diatasi | Contoh |
| TRIM | spasi berlebih di teks | TRIM(review_text_raw) |
| CLEAN | karakter non-print | CLEAN(text) |
| LOWER / PROPER | huruf campur pada kategori | PROPER(LOWER(channel_raw)) |
| XLOOKUP | mapping raw category ke standar | XLOOKUP(raw, map_raw, map_standard, "CHECK") |
| IF + ISBLANK | menandai nilai kosong | IF(ISBLANK(date),1,0) |
| COUNTIFS | menemukan kunci duplikat | COUNTIFS(id,id,date,date,text,text) > 1 |
| NUMBERVALUE | ubah teks angka jadi angka | NUMBERVALUE(value_text) |
| IFERROR | tangani error konversi (mis. tanggal tak valid) | IFERROR(DATEVALUE(date_raw),"") |
| TEXT(...,"yyyy-mm") | grouping bulanan untuk tren | TEXT(review_date_clean,"yyyy-mm") |
@trap Category mapping dianggap tidak perlu default "CHECK" :: Kalau XLOOKUP raw_channel yang tidak ada di mapping table dibiarkan default kosong atau 0 (bukan "CHECK"), nilai kategori baru yang belum terdaftar akan HILANG DIAM-DIAM dari hasil, bukannya terlihat untuk diinvestigasi. Default "CHECK" wajib supaya nilai tak-terpetakan selalu ketahuan sebelum dianggap valid.
@trap IFERROR dipakai untuk menyembunyikan error, bukan menanganinya :: IFERROR(DATEVALUE(date_raw),"") berguna supaya formula tidak crash, TAPI hasil "" (blank) dari tanggal yang gagal parse tetap WAJIB masuk data-quality log sebagai issue (mis. missing_date_flag=1) — bukan dibiarkan blank diam-diam tanpa dicatat.
